**Docker** 是一個開源的「容器化」（Containerization）平台，簡單來說，它的核心目的就是：**讓軟體在任何環境下都能以相同的方式運行。**

---

### 1. 用生活中的例子理解：貨櫃（Container）

在傳統運輸中，如果要把各式各樣的貨物（如水果、汽車、機器）裝上船，每種貨物包裝不同，搬運非常麻煩。後來人們發明了**標準貨櫃**，不管裡面裝什麼，外表規格都一樣，吊車和貨輪只要處理貨櫃即可。

* **傳統方式：** 你的程式碼就像散裝貨物。放到不同電腦（開發者電腦、測試伺服器、雲端伺服器）上時，常因為作業系統版本、環境套件不同而出現「在我電腦上可以跑，為什麼在你那裡不行？」的問題。
* **Docker 方式：** 將程式碼與它所需要的一切（作業系統核心環境、函式庫、套件、設定檔）打包成一個**標準化的容器**。不論放到哪一台支援 Docker 的電腦上，結果都是一模一樣的。

---

### 2. 容器 vs. 虛擬機器（VM）

很多人常拿 Docker 與傳統的虛擬機器（如 VMware、VirtualBox）比較：

| 特性 | 傳統虛擬機器 (VM) | Docker 容器 (Container) |
| --- | --- | --- |
| **架構** | 需要完整安裝一套**客體作業系統** (Guest OS) | 與宿主共享 OS 核心，僅隔離應用與依賴環境 |
| **啟動速度** | 較慢（需數十秒至數分鐘） | 極快（幾毫秒到數秒內） |
| **資源占用** | 很高（每個 VM 都需獨立佔用 CPU/記憶體/硬碟） | 極低（輕量級，只佔用程式執行需要的資源） |
| **部署數量** | 一台主機通常只能跑數個至數十個 | 一台主機可同時跑幾百甚至上千個容器 |

---

### 3. Docker 的三大核心概念

理解 Docker 只需搞懂這三個東西：

1. **Dockerfile（食譜 / 藍圖）：**
一個純文字檔案，裡面記錄了建置環境的步驟指令（例如：安裝 Python 3.9、複製程式碼、安裝依賴套件、設定啟動指令）。
2. **Image 鏡像（成品菜餚的凍結狀態）：**
透過 Dockerfile 編譯出來的唯讀範本。你可以把 Image 當作是應用程式的軟體安裝包。
3. **Container 容器（正在運行的實體）：**
從 Image 啟動後運行的獨立進程。一個 Image 可以同時啟動多個獨立運行的 Container。

```
[ Dockerfile ] ---> 建立 (Build) ---> [ Image ] ---> 執行 (Run) ---> [ Container ]

```

---

### 4. Docker 帶來的核心優勢

* **環境一致性：** 徹底解決「在我電腦可以 run」的部署痛點。
* **微服務架構最佳搭檔：** 方便將複雜的大型系統拆解成多個獨立服務（如：Database 容器、API 容器、前端容器）各自運行與維護。
* **快速擴展與復原：** 如果某個服務流量爆滿，可以秒級啟動多個容器來分攤流量；壞掉時也能瞬間重建。
* **生態系豐富（Docker Hub）：** 官方與社群提供了大量現成的 Image，像 PostgreSQL、Redis、Nginx 等，只需一條指令 `docker run` 就能立刻開始使用，完全免去繁瑣的安裝設定。
